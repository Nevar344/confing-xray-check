# 🚀 Remnanode Environment & Config Assistant

Автоматизированный CLI-инструмент для **предварительной проверки системного окружения** и **безопасной конфигурации** нод Xray / Remnanode.

Скрипт проверяет состояние Docker, наличие необходимых SSL-сертификатов, доступность системных портов и предоставляет интерактивный интерфейс для добавления протоколов **VLESS Reality**, **Hysteria 2**, а также тонкой настройки **DNS** и маршрутизации.

## ⚡ Быстрый запуск

Запустите следующую команду в терминале вашего сервера (требуются права **root**):

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/Nevar344/confing-xray-check/main/setup.sh)"
```

> **Альтернативный запуск напрямую через Python:**
> ```bash
> git clone https://github.com/Nevar344/confing-xray-check.git
> cd confing-xray-check
> sudo python3 main.py
> ```

## 📋 Требования к системе и проверки

Перед выполнением любых изменений конфигурации скрипт производит **8 этапов Pre-flight диагностики**:

| № | Проверяемый пункт | Критичность | Пояснение |
|---|-------------------|-------------|-----------|
| 1 | **Права root** | 🔴 Критично | Требуется для чтения/записи `/etc/remnanode/config.json` |
| 2 | **Наличие Docker** | 🔴 Критично | Проверка наличия бинарного файла `docker` |
| 3 | **Docker Daemon** | 🔴 Критично | Проверка активности сервиса Docker (`docker info`) |
| 4 | **Контейнер `remnanode`** | 🟡 Важно | Проверяет существование Docker-контейнера |
| 5 | **Статус `remnanode`** | 🟡 Важно | Проверяет, запущен ли контейнер в данный момент |
| 6 | **Доступность `/dev/shm`** | 🔴 Критично | Необходим для оперативного хранения SSL-сертификатов |
| 7 | **SSL Сертификаты** | 🟠 Блокирующе для Hy2 | Проверяет наличие `fullchain.pem` и `privkey.pem` в `/dev/shm/hy2_certs/` |
| 8 | **Порт 443/TCP (VLESS)** | 🟢 Информационно | Проверка доступности прослушивания порта 443 |

## 🛠️ Карта использования (Инструкция)

При запуске скрипта вы увидите статус системы и Главное меню:

```text
============================================================
         🔍 Проверка системного окружения
============================================================
  ✅ Запуск от root: Запуск от пользователя root
  ✅ Установка Docker: Docker установлен
  ✅ Доступность Docker daemon: Docker daemon доступен
  ✅ Наличие контейнера 'remnanode': Контейнер 'remnanode' найден
  ✅ Запуск контейнера 'remnanode': Контейнер 'remnanode' запущен
  ✅ Доступность /dev/shm: Директория /dev/shm доступна для записи
  ✅ Сертификаты SSL (/dev/shm/hy2_certs): Сертификаты найдены
  ✅ Работа VLESS Reality (443/TCP): Порт 443/TCP активен
============================================================

---------------------------------------------
Главное меню:
1. Добавить VLESS-Reality (443/TCP)
2. Добавить Hysteria 2 (443/UDP) [✅ Готово к добавлению]
3. Настроить DNS
4. Перепроверить системное окружение
5. Сохранить и выйти
```

---

### 1. VLESS-Reality (443/TCP)
- Нажмите `1` в главном меню.
- Укажите **Порт** (по умолчанию: `443`).
- Задайте **SNI / Server Name** (по умолчанию: `example.com`).
- Вставьте ваш **Private Key**, полученный из панели управления.
- Выберите вариант генерации **Short ID** (стандартный, новый случайный или свой).
- Выберите значение **PROXY protocol (xver)** (`0`, `1` или `2`).

---

### 2. Hysteria 2 (443/UDP)
> ⚠️ **Обратите внимание:** Данная опция заблокирована в меню, пока в `/dev/shm/hy2_certs/` не будут найдены файлы `fullchain.pem` и `privkey.pem`.

- Нажмите `2` в главном меню.
- Укажите UDP-порт (по умолчанию: `443`).
- Введите пароль доступа или нажмите Enter для автоматической генерации через UUIDv4.

---

### 3. Настройка DNS и Маршрутизации
- Нажмите `3` в главном меню.
- Укажите желаемый IP адрес DNS-сервера (по умолчанию: `1.1.1.1`).
- Скрипт автоматически актуализирует раздел `dns` в файле конфигурации.

## 🔒 Безопасность и Валидация

1. **Резервное копирование:** Перед внесением изменений рекомендуем сохранять оригинальный `/etc/remnanode/config.json`.
2. **Изоляция сертификатов:** Сертификаты читаются исключительно из области `/dev/shm`, что исключает лишнюю нагрузку на накопитель и повышает безопасность.
3. **Безопасные значения по умолчанию:** В коде отсутствуют захардкоженные приватные домены или секреты — все параметры используют нейтральные примеры (`example.com`).
